# Чем отличается omp-huimem

[На главную](i18n/README.ru.md) · [Как работают слои](LAYERS.md)

**Сильная сторона — проверяемая project-first память без отдельной инфраструктуры, с изолированными session и opt-in personal областями.** Сравнительный прогон против Claude Code, Hindsight или Mem0 не проводился; превосходство качества над ними не установлено.

## Выбор по задаче

| Подход | Где omp-huimem удобнее | Компромисс |
| --- | --- | --- |
| Только Markdown-заметки | Проверка цитат, версии, признаки устаревания и доставка контекста | Больше устройства, чем у одного файла |
| История диалога / сводка | Текущее решение отделено от обсуждения; исправления имеют версии | Агент всё ещё может не выделить важное |
| Сервис с LLM-извлечением | Не нужен отдельный процесс обработки памяти | Нет независимого семантического извлечения и консолидации |
| Поиск по embeddings | Не нужно вычислять embeddings и обслуживать их хранение | Текстовый поиск хуже на синонимах и перефразировании |
| Граф знаний | Проще читать текущие знания и разбирать источник записи | Есть один bounded-hop по явным dependsOn/links, но нет автоматически извлечённого semantic/causal graph |

Это сравнение подходов, а не утверждение, что каждый продукт использует все перечисленные компоненты.

## Исследование новых механизмов, октябрь 2026

Сравнивались не названия продуктов, а механизмы SimpleMem, xMemory, TiMem, MAGMA, AgeMem,
ACE, Mastra OM и MemTrace. Первоисточники, даты, проверка статьи против реализации,
наличие моделей/embeddings и границы результатов приведены в
[исследовательской записке](RETRIEVAL-RESEARCH.md#обзор-подходов-сообщества-к-октябрю-2026).

Для текущих ограничений выбран corpus-aware sparse-компонент с binary IDF, но не вся
архитектура SimpleMem. Lexical diversity отклонён после контрольных случаев с двумя
разными нужными фактами одной темы. Модельная консолидация, uncertainty gate и обучение
политики не считаются реализованными через этот локальный перенос. Существующие версии,
источники, STALE, procedure и paging не выдаются за вновь созданные механизмы.

Для 0.7.0 отдельно изучены исходники первых двадцати memory-пакетов из выдачи Pi:
версии, integrity npm-архивов, storage, retrieval и hooks, не только README. Полная
таблица пакетов и отказов — в [аудите](RETRIEVAL-RESEARCH.md). От Hermes-подобных решений
выбраны малый релевантный блок и точные оригиналы; от Wiki/state-flow — явная курация,
scope и runtime-owned source identity; от локальных поисковых решений — derived FTS
и changed-only запись. Это оригинальная интеграция механизмов, не копия всего продукта.

OptMem полезен разделением append-only log и пересобираемого дерева, но обязательные
note/nap и 280-byte записи не заменяют точное evidence. Basic Memory полезен как референс
Markdown/ссылок, не как необходимость нового MCP-реестра. OpenViking-адаптер требует
серверной/launcher инфраструктуры, которая здесь исключена. Отдельный tree-sitter repo-map
не дублирует native LSP/grep OMP: кодовая навигация остаётся в харнесе, память — в плагине.
Git history доступна по запросу и не объявляется доказательством rationale.

Результаты huimem проверяются отдельно: локальные задержки/SQL changes, fourteen context
fixtures, upgrade/rollback настоящим 0.6.10 bundle и 33 same-GPT запуска. В парных сценариях
финальные ответы прошли у обеих сборок; большего answer quality score не заявлено.
Сведения и пределы — в [VALIDATION.md](VALIDATION.md).



## Claude Code

Claude Code поддерживает инструкции проекта и автоматическую файловую память. Читаемый Markdown и сохранение между сессиями поэтому не уникальны для omp-huimem. [Официальная документация](https://code.claude.com/docs/en/memory).

Причина выбрать наш плагин — работа внутри OMP с вашей моделью и явный реестр свидетельств: цитата, версия, `STALE`. Это свойства нашей реализации, а не доказательство превосходства над Claude Code в реальных задачах.

## Hindsight

Hindsight описывает сохранение, поиск и осмысление памяти; при сохранении LLM извлекает факты, сущности и связи. [Документация](https://hindsight.vectorize.io/best-practices).

В omp-huimem знания выделяет основной агент, а код проверяет источники и хранит версии. Для машины без ресурсов на дополнительную LLM-обработку это практическое преимущество. Взамен полнота сохранения зависит от основной модели. Опыт отдельной неудачной установки не означает, что Hindsight в целом ненадёжен.

## Mem0

Документированный механизм Mem0 включает LLM-извлечение фактов и векторное представление для поиска. Возможности зависят от версии и конфигурации. [Описание механизма](https://docs.mem0.ai/core-concepts/memory-evaluation).

В omp-huimem такой отдельной обработки нет. Плюс — меньше компонентов для запуска и диагностики; минус — нет semantic retrieval. В 0.7.0 локальный FTS измерен на архиве 26 млн UTF-16 единиц; скорость поиска не является доказательством качества на произвольном большом корпусе.

## Преимущества, подтверждённые устройством кода

- **Не нужна вторая нейросеть.** Расширение не вызывает LLM, не создаёт очередь извлечения и не запускает фоновые задания.
- **Понятно происхождение записи.** Источник проверяется до записи; уверенного текста агента недостаточно для принятого решения.
- **Исправления сохраняют историю.** Версии и проверка ожидаемой версии защищают реестр от тихой перезаписи.
- **Знания доступны без плагина.** Основные файлы остаются Markdown/JSON после отключения расширения.
- **Размер контекста ограничен.** У блока памяти явный предел; стоимость всей сессии при этом не фиксирована.

## Когда выбрать другое решение

Для upstream Pi адаптер ещё не готов. Для поиска по смыслу в тысячах документов стоит оценить специализированный поиск. Общая память команды, разграничение доступа и синхронизация между сервисами здесь не реализованы.

Для OMP и ограниченных ресурсов это project-first компромисс с явным opt-in для personal: меньше инфраструктуры, проверяемые источники и история изменений. Проверенные сценарии и границы — в [VALIDATION.md](VALIDATION.md).

Базовые продуктовые описания проверялись 8 сентября 2026 года; источники и методы нового исследования — 21 октября. Локальные сравнения retrieval не заменяют испытание на ваших задачах.
