один запрос в трёх условиях — без расширения, сборка `v0.9.0`, сборка 0.9.1. Нужное знание лежит

Набор — `bench/tasks.ts`, запуск — `bun bench/run.ts` (описание параметров в начале `bench/run.ts`).

- **Исправления сравнения после первого прогона.** `preference-layout` требовал имя
  `util-slugify.ts`, а модель с памятью трижды следовала соглашению с именем `util-slug.ts`;

  `procedure-how` без памяти решается по подсказке usage скрипта — задача слабее, чем задумана.
- **Ограничения.** Два повтора, одна локальная модель, синтетические проекты; пять из девяти задач
  построены под изменения выпуска и поэтому показывают их лучшую сторону. Это проверка того, что
  изменения работают в исполнении, а не оценка памяти в целом.

## Выпуск 0.8.7: работа из коробки и короткий экран /huimem, 25 октября 2026

Причина пропажи `project_memory` после approve подтверждена на официальном OMP 18.12.6, без
изменения OMP. При свежем интерактивном запуске расширения грузятся после первого кадра;
`plan.defaultOnStartup: true` входит в план раньше и запоминает набор инструментов без
`project_memory`, а после approve восстанавливает его. При `--resume` загрузка немедленная.

- Воспроизведение на 0.8.5: после approve модель сообщила, что `project_memory` нет в списке.
  С `plan.defaultOnStartup: false` и `/plan` тот же сценарий выполнил `doctor` без замечаний.
- Проектный `.omp/config.yml` перекрывает глобальное значение (`omp config get` в каталоге с
  `true`/`false` при глобальном `false`). Поэтому starter записывает `defaultOnStartup: false`.
- Установленный 0.8.7, план при запуске через временный оверлей: после approve блок сказал
  `PROJECT_MEMORY_TOOL_UNAVAILABLE`; модель не искала инструмент, назвала причину и способ
  исправления. `/huimem` показал 6 пунктов и предупреждение в заголовке. Явно загруженный
  через `-e` плагин грузится сразу, поэтому этот путь сбой не воспроизводит.
- Тесты до исправления: 6 ожидаемых отказов (скрытый инструмент, экран, уведомление архитектуры);
  после: `bun run check` — 469 pass, 1 skip, 0 fail.

Плагин сам инструмент не включает: в ограниченной сессии это был бы обход разрешений. Схема 2,
доказательства, optional commit и `loadMode: essential` не менялись; функции экрана перенесены
в подменю, не удалены.

### Исправленные причины и проверки

- Первый `agent_end` не всегда означает конец native recovery. Привязка точного
  learning packet теперь живёт до публичного command-context `waitForIdle`;
  пользовательское прерывание отдельно освобождает команду и не подтверждает пакет.
- Ошибка task label, даже содержащего слово `database`, не отравляет health.
  Настоящий native SQLite/filesystem code имеет приоритет над validation-похожим
  текстом. Реальные SQLite triggers проверяют и отказ записи, и отсутствие checkpoint.
- Новые captures маскируют распознанные значения GitHub/Slack credentials, AWS access
  IDs, URL passwords и private keys, включая незакрытый PEM. Новая запись не может
  скопировать такую quote из старого оригинала. Старые источники **не переписываются**:
  они могут содержать credentials; их нужно проверить перед отправкой модели или публикацией.
  Имена переменных, инструкции о `.env`, кириллица и emoji остаются допустимыми.
- Wiki read/list/lint используют один согласованный read snapshot и общие проверки
  внутри операции. Следующий вызов заново замечает изменённый файл или версию записи.
  Publication сохраняет независимые проверки и write guards; TTL нет.
- Обычный индекс `episodes(role,time DESC)` заменяет полный поиск кандидатов
  дедупликации. Оригиналы, роли, окно дедупликации, schema **2**, **11 primary tables**
  и `WAL/FULL` сохранены.

До реализации наблюдались предметные падения: исходные регрессии capture/lifecycle/health,
отдельный отказ проверки secret-bearing quote и два случая native-code precedence.

## Явное включение по проекту

Замерено на голом каталоге: расширение создавало `.memory/runtime/state.sqlite` в любом проекте, где запущен OMP, записывало эпизоды и выдавало `ARCHITECTURE_UNCONFIGURED` — при `versions=0, checkpoints=0`, поскольку писать было некуда. В чужом репозитории такая база не покрыта `.gitignore`.

С версии 0.2.0 признак включения — `.memory/MEMORY.md`. Проверено живыми сессиями: в каталоге без него после сессии не осталось ни одного файла, кроме исходного `main.py`, и вывод чист; в развёрнутом проекте контекст и запись эпизодов работают по-прежнему. Каталог `.memory/`, оставшийся от прежних самозапусков, включением не считается.

## Автозапись и реальное сжатие (2026-09-09)

Один изолированный прогон v0.3.0 на той же локальной Qwen: обычная просьба изменить константу с указанием причины, без «запомни», привела к обновлению MEMORY.md, созданию ADR и записи решения в SQLite. Снимок снят до вопроса на воспоминание: одна версия и один checkpoint.

Затем выполнено настоящее ручное сжатие через RPC OMP. Для короткого теста только в тестовом проекте `keepRecentTokens` уменьшен до 512: активная история сократилась с 16 сообщений до 3, исходный запрос заменён сводкой. Это не проверка автоматического сжатия при заполнении окна. И после сжатия, и в новой сессии модель восстановила три исходных значения.

**Выявлен дефект качества:** модель добавила в принятый ADR неподтверждённые последствия и оценку альтернатив. Они перешли в сводку сжатия и в оба последующих ответа. Точная цитата в реестре была корректна, но она не проверяет свободный текст ADR. Поэтому этот прогон подтверждает сохранение и перенос фактов, одновременно показывая отсутствие полной защиты от закрепления домыслов.

Проверка использовала starter, один явно загруженный bundle и отключённые skills. Один прогон не доказывает устойчивую автозапись; результат после сжатия зависит также от нативной сводки OMP.
