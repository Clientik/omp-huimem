# Архитектурные решения

Записывай уже согласованные значимые решения без отдельного напоминания.
Файл `NNNN-название.md`. Структура обязательна, а не желательна: расширение читает
именно её и объявляет цитируемым **только блок «Основание»**.

```markdown
# NNNN — краткое название

- Статус: принято | proposed
- Дата: ГГГГ-ММ-ДД

## Решение
Одно предложение: что делаем.

## Основание
> «дословная цитата пользователя или первоисточника»

Причина (дословно из основания): <фрагмент цитаты, без пересказа>

## Способ проверки
[?] не проверено: чем и когда убедиться, что решение работает.
```

**Блок «Основание» обязателен и должен содержать строку-цитату, начинающуюся с `>`.**
Документ без такого блока свидетельством не считается: при чтении расширение прямо
скажет, что подтверждённого основания в нём нет. Это не объявляет документ ложным —
он просто перестаёт быть источником авторитета.

Статус «принято» относится к решению, **а не ко всем предложениям документа**. Всё, что
вне цитаты — интерпретация: причина своими словами, альтернативы, последствия, оценки.

Альтернативы и последствия добавляй только при наличии источника; если данных нет,
раздел опусти, а не заполняй правдоподобным. Собственные выводы помечай `[?]`
«не проверено» и не приписывай их пользователю. При ответе «почему» цитируй основание,
а не догадку. Пересмотр связывай ссылкой с заменённым ADR. Не объявляй предложение
модели принятым.
